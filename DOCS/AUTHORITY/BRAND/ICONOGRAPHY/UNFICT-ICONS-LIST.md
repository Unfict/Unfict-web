The current v0.3 already establishes the core naming convention (`uf-icon-*`, `uf-motif-*`), 6 Brand Motifs, 23 Functional UI icons, and 24 Domain & Concept icons. I would preserve all of those IDs and expand around them rather than renaming or duplicating concepts. 

Below is a proposed **UNFICT Master Icon Inventory**. “Defined” means already specified in v0.3; “Proposed” means a useful extension to the library, not authorization of a product capability. That distinction follows the existing rule that icon existence does not imply capability availability.

## Proposed master inventory size

This gives Unfict a practical first master catalog of **about 100 assets**, while keeping only the existing 53 as presently defined by v0.3 and treating the rest as candidates.

I would **not generate all of them immediately**. The strongest approach remains the one already prescribed by the iconography doctrine: freeze the visual grammar through the pilot first, then expand by semantic need. 

The important architectural distinction is that this inventory now gives us three kinds of things:

**generic actions** such as Search, Edit and Download; **Unfict semantic nouns** such as Resolver, Authority and Receipt; and **domain specializations** such as GTIN, QR Code and DPP.

That separation will matter when we write the **Part 2 — Function** prompt for each icon. The same Universal Illustration Design Instruction can remain fixed, while each row above becomes a governed Function specification.
